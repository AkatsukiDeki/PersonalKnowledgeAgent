Нужно написать свой модуль Terraform, который содержит всю необходимую инфраструктуру для деплоя полноценного приложения в Облаке: набор виртуальных машин и набор дисков для бэкапов и логов, подключённых к машине.

Модуль должен разворачивать две виртуальные машины: `web` и `api`. К машине `api` должны подключаться дополнительные диски. Машины должны быть подняты в существующей подсети: `default-ru-central1-a`, публичные адреса машинам **не нужны**.

## Задание

Подготовьте новый репозиторий в [GitLab практикума](https://praktikum.gitlab.yandexcloud.net/). Назвать его можно так: `Terraform module homework`. Сделайте новую ветку с любым именем.

Вам нужно написать собственный модуль, который поднимает в Облаке нужные ресурсы:

- `resource "yandex_compute_instance" "api"`
- `resource "yandex_compute_instance" "web"`
- `data "yandex_vpc_subnet" "default_subnet"`
- `resource "yandex_compute_disk" "extra_disks"`

Описание незнакомых ресурсов можно посмотреть в документации — например, [compute disk](https://yandex.cloud/ru/docs/terraform/resources/compute_disk).

Информацию о текущей подсети можно взять из блока `data`. Это [специальный тип блока](https://developer.hashicorp.com/terraform/language/block/data), который берёт **только метаинформацию** об уже созданных ресурсах и не управляет ими.

```
data "yandex_vpc_subnet" "default_subnet" {
  name = "default-ru-central1-a"
} 
```

После чего обратиться к нему при создании ВМ:

```
resource "yandex_compute_instance" "web" {
  network_interface {
      subnet_id = data.yandex_vpc_subnet.default_subnet.id
      nat       = false
  }
  ...
} 
```

На вход в модуль должны поступать следующие **пять** input-переменных (их типы и смысл описаны ниже): `extra_disk_names`, `extra_disk_type`, `extra_disk_size`, `vm_specification`, `ssh_public_key`.

Переменные описания дополнительных дисков:

- `extra_disk_names`. Тип `list`. Список дисков, которые подключаются к ВМ `api`. По умолчанию достаточно двух значений: `"logs", "backup"`
- `extra_disk_type`. Тип `string`. Значения должны быть только `network-hdd` или `network-ssd`. По умолчанию: `"network-hdd"`
- `extra_disk_size`. Размер дополнительных дисков. Тип `number`. Значение по умолчанию: `20`.

Переменные для конфигурации ВМ:

- `vm_specification`. Переменная, включающая в себя все параметры поднимаемых ВМ.

Тип:

```
type = map(object({
  cores     = number
  memory    = number
  disk_size = number
  boot_disk = string
})) 
```

Значение по умолчанию:

```
default = {
  web = {
    cores     = 2
    memory    = 2
    disk_size = 10
    boot_disk = "fd845dr9j4h2aaq1m6ko"
  },
  api = {
    cores     = 2
    memory    = 2
    disk_size = 10
    boot_disk = "fd845dr9j4h2aaq1m6ko"
  }
} 
```

Где `cores` может принимать значение `2`, `memory` — `2` или `4`, а `disk_size` > `1`.

- `ssh_public_key`. Публичный ключ обоих ВМ, тип `string`.

На выходе должны быть следующие значения:

- список ID дополнительных дисков;
- внутренние IP-адреса ВМ.

**Обязательно сделайте (нужно выполнить все пункты):**

1. **Несколько модулей.** Разбейте конфигурацию минимум на **два дочерних модуля** (например: отдельно вычислительные ресурсы и диски, либо отдельно `web` и `api`, либо сеть/данные и ВМ). Корневой модуль или «точки входа» по окружениям должны вызывать дочерние через `module` и передавать в них переменные явно.
2. **Несколько окружений.** Подготовьте **два окружения** — `dev` и `prod`: отдельные файлы значений (`terraform.tfvars.dev`, `terraform.tfvars.prod`) с различающимися параметрами `vm_specification` и/или дисков. В README кратко опишите, как запускать `plan`/`apply` для каждого окружения.
3. **Версии Terraform и провайдера.** В блоке `terraform` укажите `required_version` и `required_providers`: зафиксируйте минимально поддерживаемую версию Terraform и провайдер Яндекс Облака (`source = "yandex-cloud/yandex"`) с осмысленным ограничением по версии (`version = ...`). Так конфигурация одинаково собирается у студента, у наставника и в CI — это базовая практика, близкая к production.
    
    Пример структуры (диапазоны подставьте под тот Terraform и тот релиз провайдера, с которыми у вас стабильно проходит `plan`):
    
    ```
    terraform {
      required_version = ">= 1.5.0"
    
      required_providers {
        yandex = {
          source  = "yandex-cloud/yandex"
          version = "~> 0.100"
        }
      }
    } 
    ```

### Чеклист самопроверки

- В корне (или в отдельном файле вроде `versions.tf`) объявлен блок `terraform` с `required_version` и `required_providers` для `yandex-cloud/yandex`
- Написан рабочий модуль: `terraform init`, `terraform plan`, `terraform apply` завершаются без ошибок
- Блоки ресурсов не содержат жёстко заданных значений (hardcodes): всё описано через `variables` и/или `locals`, если они есть
- Модуль разворачивает две VM: `web` и `api`, а также список дисков, подключённых к `api` c помощью блока `dynamic` обе подключены к подсети `default-ru-central1-a` через `data.yandex_vpc_subnet.default_subnet` **без** публичных IP (`nat = false`)
- Используются все input-переменные из задания: `vm_specification`, `ssh_public_key`, `extra_disk_names`, `extra_disk_type`, `extra_disk_size`
    - в соответствии с типами и значениями по умолчанию из задания.
- У переменных с ограничениями по допустимым значениям есть блоки `validation` (как минимум для `vm_specification`, `extra_disk_type`, `extra_disk_size`)
- Минимум два дочерних модуля с вызовом из корня (или из каталогов окружений), **и** окружения `dev` и `prod` с понятной инструкцией запуска в README
- Вывод модуля соответствует требованиям, например:

```
Outputs:

disk_ids = {
  "backup" = "fhm4dqu2v4a3qtbq1gpg"
  "logs" = "fhmqael9b45a5tgru0h1"
}
private_ips = {
  "api_vm" = "10.128.0.16"
  "web_vm" = "10.128.0.32"
} 
```

Важные моменты

- Модуль создаёт нужную инфраструктуру и возвращает нужные переменные.
- После проверки не забудьте выполнить `terraform destroy`, чтобы удалить поднятую инфраструктуру.
- В Git-репозитории сохранён исходный код, а ссылка на MR отправлена на проверку.

**Подсказка 2**

Переменную `vm_specification` можно проверить на корректность, например с помощью цикла и встроенной функции `alltrue()`:

```
validation {
  condition = alltrue([
    for vm in values(var.vm_specification) :
    vm.cores == 2 &&
    (vm.memory == 2 || vm.memory == 4) &&
    vm.disk_size > 1
  ])
  error_message = "Only available 2 cores, 2 memory or 4 memory and disk must be > 1gb"
} 
```
