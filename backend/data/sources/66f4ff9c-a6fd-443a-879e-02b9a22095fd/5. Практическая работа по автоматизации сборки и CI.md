### Задание 3. Параллельный запуск тестов и интеграция JUnit XML Отчетов

#### Задача

Добавить в этап тестирования джоб `tests` с параллельным запуском `pytest` и выгрузкой отчетов в формате JUnit для интерфейса GitLab.

#### Что было сделано

В `.gitlab-ci.yml` добавлен новый джоб `pytest_tests` в stage `test`:

YAML

```YML
pytest_tests:
  stage: test
  before_script:
    - python -m pip install --upgrade pip
    - pip install pytest
  script:
    - pytest --junitxml=report.xml
  artifacts:
    when: always
    paths:
      - report.xml
    reports:
      junit: report.xml
    expire_in: 1 week
```

#### Инженерное обоснование ("Почему именно так")

- **Параллелизация (Parallel Execution):** Помещение `lint` и `tests` в один stage позволяет GitLab Runner выполнять их одновременно, сокращая время Feedback Loop для инженера.
    
- **Интеграция с GitLab UI:** Использование директивы `artifacts.reports.junit` автоматически распарсивает XML-отчет и выводит подробный виджет со статусом каждого юнит-теста прямо на странице Merge Request / Pipeline.
    
- **Сбор артефактов при падениях (`when: always`):** Файл отчета выгружается даже при статусе `failed`, давая возможность локализовать проблему без чтения полотна сырых логов.
    

### Задание 4. Автоматизация сборки артефактов дистрибутива (`sdist` & `wheel`)

#### Задача

Добавить stage `build` для компиляции пакета приложения через `python -m build --sdist --wheel` с выходом в папку `dist/`. Сборка должна запускаться только после прохождения проверок качества.

#### Что было сделано

Добавлен джоб `build_package` на стадии `build`:

YAML

```YML
stages:
  - test
  - build

# ... [stage test] ...

build_package:
  stage: build
  before_script:
    - python -m pip install --upgrade pip
    - pip install setuptools wheel build
  script:
    - python -m build --sdist --wheel
    - ls -lh dist
  artifacts:
    paths:
      - dist/
    expire_in: 1 month
```

#### Инженерное обоснование ("Почему именно так")

- **Строгая последовательность фаз:** По методологии 12-Factor App (`Build, release, run`), стадия `build` выполняется строго после успешного прохождения стадии `test`.
    
- **Артефакты поставки:** Создаются сразу два типа пакетов: `sdist` (исходный код `.tar.gz`) и `wheel` (скомпилированный бинарный артефакт `.whl`). Секция `artifacts.paths` сохраняет папку `dist/` в хранилище GitLab.

### Задание 6. Оптимизация и рефакторинг конфигурации (DRY)

#### Задача

Вынести повторяющиеся команды установки системных зависимостей Python из внутренних джобов в общую централизованную секцию.

#### Что было сделано

Реализован итоговый манифест `.gitlab-ci.yml` с использованием секции `default.before_script`:

YAML

```YML
default:
  image: python:3.13
  before_script:
    - python -m pip install --upgrade pip
    - pip install flake8 pytest setuptools wheel build

stages:
  - test
  - build

# --- STAGE 1: QUALITY & TESTING (Parallel execution) ---
lint:
  stage: test
  script:
    - flake8 hello tests

tests:
  stage: test
  script:
    - pytest --junitxml=report.xml
  artifacts:
    when: always
    paths:
      - report.xml
    reports:
      junit: report.xml
    expire_in: 1 week

# --- STAGE 2: BUILD ARTIFACTS ---
build:
  stage: build
  script:
    - python -m build --sdist --wheel
    - ls -lh dist
  artifacts:
    paths:
      - dist/
    expire_in: 1 month
```

#### Инженерное обоснование ("Почему именно так")

- **Принцип DRY (Don't Repeat Yourself):** Устранена дубликация вызовов `pip install` из каждого отдельного джоба.
    
- **Упрощение поддержки (Maintainability):** Добавление нового инструмента или изменение версии пакета теперь выполняется в одном месте (`default.before_script`), исключая рассинхронизацию окружений между задачами.
