# Personal Knowledge Agent (PKA) — Version 1.1.0 (Graph-Augmented RAG)

**Что нового (Changelog):**

* **v1.4 Vision & Multimodality:** Добавлена полноценная мультимодальность с использованием `qwen2.5-vl` и Gemini Vision. Теперь можно прикреплять изображения, а PKA проанализирует их. Внедрена система **Visual Priority**: изоляция обработки новых изображений от истории диалога для предотвращения смешения контекста (Context Bleed). Также внедрен бронебойный джейлбрейк для принудительного анализа лиц и людей на фотографиях в обход базовой цензуры LLM.
* **v1.4 Two-Tier Grounding (Hybrid Fallback):** Полностью устранены жесткие тупики `INSUFFICIENT_DATA`. Если в базе RAG нет точного ответа на вопрос пользователя, PKA честно признается об отсутствии данных в базе, после чего дает развернутый ответ на основе общих знаний и эрудиции LLM (гибридный ответ).
* **v1.3 Background Automation & Dogfooding:** Внедрен фоновый демон `vault_watcher.py` как «прозрачная труба» для автоматической синхронизации заметок (из локального хранилища Obsidian) в базу знаний без блокировки основного веб-сервера. Реализованы механизмы debounce-буферизации, фильтрации системных директорий и предотвращения дублирования Ingestion-задач на основе сверки SHA-256 хешей файлов. Проведены доработки интерфейса (SPA-навигация инсайтов, сброс фокуса графа) для старта боевой фазы Dogfooding.
* **v1.2 Error Registry & Operational Telemetry Layer:** Операционный слой телеметрии и авторазрешения ошибок. Таблица `system_errors` сохраняет детали сбоев с надежной защитой от галлюцинаций трекера (Fail-Safe), фильтрует конфиденциальные данные (Sanitization) и сводит одинаковые ошибки по стабильным фингерпринтам (Fingerprinting). Успешные процессы (включая конвейер инжестии) точечно закрывают старые ошибки (Granular Resolution). Управление доступно через REST API.
* **v1.1 Proactive Engine:** Добавлен фоновый планировщик (`scheduler.py`), который периодически отслеживает поток новых фактов ($\Delta\text{claims} \ge 20$ или $\Delta\text{domains} \ge 2$) и запускает движок поиска макро-инвариантов. Реализован UI-модуль Proactive Insights ("Я заметил..."), позволяющий пользователю подтверждать (Accept) или отклонять (Dismiss) гипотезы. Только подтвержденные инсайты попадают в L3-слой RAG, надежно защищая контекст от галлюцинаций.
* **v1.1.0 Graph-Augmented RAG (L1-L4):** Переход от плоского векторного поиска к графовой структуре контекста. Агент теперь извлекает не только точные фрагменты текста `[L1 CHUNK]`, но и атомарные факты `[L2 CLAIM]`, глобальные паттерны `[L3 PATTERN]` и временные связи `[L4 TEMPORAL/CONFLICT]`.
* **v1.1.0 Dual-Pipeline Retrieval:** Встроенный классификатор намерений маршрутизирует запросы. Фактологические запросы (FACTUAL) используют строгие пороги (Strict Gate), исключая галлюцинации. Аналитические запросы (ANALYTICAL) используют мягкие пороги для сборки широкого графового контекста.
* **v1.1.0 Batch Ingestion:** Пакетная векторизация и экстракция данных (Claims, Entities, Relations) через LLM, снижающая накладные расходы и ускоряющая обработку документов.
* **v1.1.0 Query Condensation:** Умная обработка контекстных вопросов. Теперь агент помнит историю диалога и автоматически переписывает короткие уточняющие реплики (например, «а подробнее?») в полноценные поисковые запросы для точного векторного поиска.
* **v1.1.0 Source Manager:** Полноценный UI-менеджер источников (L1 Memory). Теперь можно просматривать список загруженных документов и удалять их в один клик.

Personal Knowledge Agent (PKA) — это мультимодальная RAG (Retrieval-Augmented Generation) система для создания личной базы знаний. 
Система позволяет загружать заметки, документы, изображения и сниппеты кода, векторизовать их, сохранять в базу данных с поддержкой векторного поиска (pgvector) и вести осмысленный диалог с агентом (на базе Qwen 2.5, Gemini), который опирается на загруженные данные и связи между ними. Изображения можно открывать в удобном полноэкранном режиме, а диалог поддерживает гибридный режим Two-Tier Grounding, балансируя между личными знаниями и общей эрудицией ИИ.

### 🎓 Модуль обучения и персональный AI-Тьютор (Learning Engine)

- **Интерактивная дорожная карта (Roadmap)**:
  - Автоматическая генерация пошагового графа тем на основе фактов из привязанных источников (`Source` -> `Claim`).
  - Динамическое отслеживание прогресса: статусы *В очереди*, *В процессе*, *Освоено*.
  - Автоматический пересчет метрики освоения предмета (`Mastery Score`).

- **Кастомная практика и Exam Mode**:
  - Гибкая настройка тренировок: выбор типа (*Квиз* / *Флеш-карточки*), области фокусировки (весь предмет, отдельная тема дорожной карты или конкретный документ) и уровня сложности (*Базовый*, *Средний*, *Хардкор*).
  - **Exam Mode**: экзаменационный режим на 15 комплексных вопросов с общим таймером (15 минут), скрытием моментальных подсказок и сводным экраном разбора ошибок. Статус `Mastered` при сдаче $\ge 85\%$.

- **Персистентный Сократовский Smart Tutor**:
  - Непрерывный диалог с сохранением истории сообщений в PostgreSQL (`SubjectTutorConversation` / `SubjectTutorMessage`).
  - Обучение в стиле Сократа: наводящие вопросы и фокус на практическое понимание вместо выдачи сухих лекций.
  - Сквозной контекст: быстрый переход к разбору конкретной темы прямо из карточки Roadmap.
  - Ручное управление контекстом и очистка диалога.

- **Аналитика и GitHub Activity Heatmap**:
  - Интерактивный тепловой календарь сессий за последние 16 недель.
  - Подсчет текущего стрика занятий (дни подряд).
  - Фильтрация аналитики по временным окнам: 7 дней, 30 дней, сезон (3 месяца / 90 дней), всё время.
  - Автоматическое выявление топ-5 слабых мест и концепций, требующих повторения.

## 🧠 Архитектура и Логика

### 1. Ingestion (Загрузка знаний)
- Пользователь через UI (`SourceUploader.tsx`) отправляет текст (заметку, код).
- Frontend вызывает `POST /api/v1/sources`.
- Backend (`knowledge.ingestion`) создает запись `Source` в БД.
- Текст разбивается на смысловые фрагменты (`knowledge.chunking`).
- Для каждого фрагмента генерируется векторное представление (эмбеддинг) через **BGE-M3** (локально) или **Gemini API**.
- В фоне qwen2.5-coder извлекает из чанков атомарные факты (`Claims`), сущности и формирует графовые связи.
- Фрагменты (`Chunk`) сохраняются в PostgreSQL с использованием типа `vector(1024)` из расширения **pgvector**, а также генерируется `tsvector` для полнотекстового поиска.

### 2. Intent Classification & Retrieval (Гибридный поиск)
- При запросе пользователя Backend (`knowledge.intent_classifier`) определяет интент: `FACTUAL` или `ANALYTICAL`.
- Выполняется **Hybrid Search** (векторный HNSW + полнотекстовый GIN) с алгоритмом **RRF (Reciprocal Rank Fusion)**.
- **Context Builder** формирует контекст:
  - Для `FACTUAL` используется строгий порог, возвращаются только точные `[L1 CHUNK]`.
  - Для `ANALYTICAL` используется мягкий порог, а контекст обогащается `[L2 CLAIM]`, `[L3 PATTERN]` и `[L4 TEMPORAL/CONFLICT]` (хронологические связи, противоречия).

### 3. Generation (Генерация ответа)
- Найденный многоуровневый контекст подставляется в системный промпт (`agent.prompts`). Если контекста недостаточно, активируется гибридный фоллбэк (Two-Tier Grounding).
- Промпт отправляется в **Gemini 2.5 Flash** (или локальную LLM `qwen2.5-coder`) через `agent.gemini`.
- Агент формирует аналитический или фактологический ответ и возвращает его пользователю.
- Если к сообщению прикреплено **изображение**, RAG временно отключается, а история диалога игнорируется (Visual Priority), чтобы избежать "галлюцинаций контекста". Картинка обрабатывается через локальную `qwen2.5-vl` или `Gemini Vision` со строгим разрешением на анализ лиц (Override Filters).
- Backend передает ответ клиенту через **Server-Sent Events (SSE)**, обеспечивая стриминг текста в реальном времени, а также передает список использованных источников (Citations).

## 🚀 Запуск проекта

1. **База данных и Backend**
   ```bash
   # Запуск PostgreSQL с pgvector и Backend-сервера
   docker-compose up -d
   ```

2. **Frontend**
   ```bash
   cd frontend
   npm install
   npm run dev
   ```

Откройте `http://localhost:5173` в браузере для доступа к интерфейсу агента.
